# 异动分析 ReAct 第一版验证记录

日期：2026-10-26。范围：项目当前配置的数据、模型与检索服务；单个案例，不代表准确率基准。

## 离线验证

87 项 unittest 通过，另执行主图与子图接线断言。
覆盖动作白名单、固定维度排除、真实分组引用、范围继承、对账、拆解、重复动作、错误/超时、
取消传播、预算耗尽、检查点状态与既有指标/取值关联回归。

## 真实端到端联调

问题：为什么2025年7月上海销售额比2025年6月下降了？

入口：Orchestrator → 异动分析主图 → 分析子图；实际调用模型、MySQL、Qdrant 和 Elasticsearch。
未强制指定 Agent 动作，也未用 mock 替代线上依赖。

总体：187106.97 → 121051.29，净变化 -66055.68，下降约 35.30%。

| 动作 | 范围与结果 | 证据校验 |
| --- | --- | --- |
| metric_decomposition | 上海；订单数量 38 → 27；数量因素分摊约 -51739.87，平均订单金额因素约 -14315.81 | ok，保留两期 SQL |
| dimension_contribution | 上海，按门店；南京东路旗舰店变化 -83671.56，微信商城自营店变化 +17615.88 | ok，两期分组分别与上海总体对账 |
| dimension_contribution | 上海且门店为南京东路旗舰店，按促销活动下钻；基准净变化 -83671.56 | ok，两期分组分别与父门店基准对账 |

模型实际路径为“指标拆解 → 门店贡献 → 真实门店分组中的促销活动下钻”。
共完成 8 次业务取数：总体两期，三个动作各两期；不包含 EXPLAIN 等校验请求。
最后返回 stop_reason=budget_exhausted、completion_status=partial。
这是三轮硬预算正常生效；已验证证据保留，未把预算耗尽表述成全部分析完成。

本轮不能证明促销活动导致了下降，也不能据此评估普遍的结论正确率或质量提升。
不同视角的贡献不得相加，父子范围的贡献也不得相加。

## 环境修复与观察

首次在受限网络环境运行，模型连接失败；当前虚拟环境还缺少 greenlet，导致 SQLAlchemy 清理阶段异常。
安装 greenlet 后在允许访问项目依赖的环境中重试，完整链路返回报告。
已将 sqlalchemy 的 asyncio extra 纳入项目依赖，并补齐锁文件已有、代码使用的 langchain-community 与 zhipuai 声明。

Qdrant 客户端输出版本兼容性警告：客户端 1.16.2、服务端 1.18.2；本次检索成功，未在本任务中升级它们。

实际联调还发现拆解结果的高精度 Decimal 在报告中过长；已调整为仅展示两位小数，
结构化原值和计算精度保持不变，并补充离线断言。
