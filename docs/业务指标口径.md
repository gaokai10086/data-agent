# 业务指标口径

本文记录已经发布到 Meta 数据库、并被 Agent 使用的业务指标。指标口径由业务人员定义，系统只做技术校验。

## 1. 销售额

| 项目 | 内容 |
| --- | --- |
| 指标名称 | 销售额 |
| 英文标识 | `sales_amount` |
| 业务定义 | 订单状态为“已完成”的订单实际支付金额之和 |
| 计算公式 | `SUM(fact_order.pay_amount)` |
| 事实表 | `fact_order` |
| 度量字段 | `pay_amount` |
| 聚合方式 | `SUM` |
| 固定过滤 | `fact_order.order_status = '已完成'` |
| 默认时间字段 | `fact_order.pay_time` |
| 业务别名 | 销售金额、成交金额、实付金额 |
| 可分析维度 | 支付时间、门店、大区、渠道、用户、促销活动 |

关键口径说明：

```text
1. 只统计已完成订单，待付款、已发货、已退款、已取消都不计入
2. 使用订单实际支付金额 pay_amount，不使用优惠前原价 original_amount
3. 使用订单粒度，不使用商品明细的 total_sales_amount
```

标准 SQL 模板：

```sql
SELECT SUM(pay_amount) AS sales_amount
FROM fact_order
WHERE order_status = '已完成'
```

## 2. 订单数量

| 项目 | 内容 |
| --- | --- |
| 指标名称 | 订单数量 |
| 英文标识 | `order_count` |
| 业务定义 | 订单状态为“已完成”的去重订单数 |
| 计算公式 | `COUNT(DISTINCT fact_order.order_sn)` |
| 事实表 | `fact_order` |
| 度量字段 | `order_sn` |
| 聚合方式 | `COUNT_DISTINCT` |
| 固定过滤 | `fact_order.order_status = '已完成'` |
| 默认时间字段 | `fact_order.pay_time` |
| 业务别名 | 完成订单数、成交订单数 |
| 可分析维度 | 支付时间、门店、大区、渠道、用户、促销活动 |

关键口径说明：

```text
1. 使用 COUNT(DISTINCT order_sn)，避免与明细表关联时订单被重复计数
2. 不使用明细表行数，因为一笔订单可以包含多件商品
3. 与销售额保持一致的订单状态口径，都只统计已完成
```

标准 SQL 模板：

```sql
SELECT COUNT(DISTINCT order_sn) AS order_count
FROM fact_order
WHERE order_status = '已完成'
```

## 3. 口径与字段的对应关系

```text
销售额   → fact_order.pay_amount
订单数量 → fact_order.order_sn
时间维度 → fact_order.pay_time
状态过滤 → fact_order.order_status
区域维度 → dim_store.region
```

## 4. 指标如何维护

指标不再写死在代码里，而是存在 Meta 数据库的 `metric_info` 表中：

```text
metric_info.status = draft / published / deprecated
```

维护流程：

```text
业务人员在 Web 页面「元数据管理 → 指标管理」提交指标
    ↓
系统校验事实表、度量字段、时间字段、过滤字段、维度字段是否存在
    ↓
校验通过后直接写入 metric_info，状态为 published
    ↓
自动生成 column_metric 公式血缘
    ↓
重建 Qdrant 指标索引后，Agent 才能召回该指标
```

重建指标索引：

```bash
python -m app.scripts.rebuild_metric_index
```

## 5. 常见错误口径

以下是容易被模型误用的口径，需要明确排除：

| 错误写法 | 问题 |
| --- | --- |
| `SUM(original_amount)` | 这是优惠前原价，不是实付金额 |
| `SUM(fact_order_detail.total_sales_amount)` | 这是商品明细口径，与订单口径不一致 |
| `COUNT(*) FROM fact_order_detail` | 这是明细行数，不是订单数 |
| 不带 `order_status = '已完成'` | 会把退款、待付款订单算进来 |

这些错误口径在评测集中都有对应题目，见 [评测框架说明](评测框架说明.md)。
